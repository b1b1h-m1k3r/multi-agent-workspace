# Global rules for Codex

- **Agents Workspace (shared multi-agent projects)**: `{{WORKSPACE}}` is the shared parent folder for work across several agents. Read `{{WORKSPACE}}/AGENTS.md` before working anywhere inside it. Short version: your agent name is `Codex`. Start work on a project with `{{WORKSPACE}}/_scripts/new-version.sh <project> Codex`, edit only the `Codex/<version>/` folder it prints, never `main/` or another agent's folder, and publish with `{{WORKSPACE}}/_scripts/publish-version.sh <project> Codex <version>`. Never hand-edit `main/` or `LAST-EDITED-BY.md`. If a project under `Projects/` is flat (no `main/` or `<Agent>/<version>/` folders), retrofit it first as AGENTS.md describes, including empty `v1/` placeholders for every other agent. Build, install and deploy anything persistent from `main/`, never from your working copy.
- **No dated or chat folders**: never create a folder named after a date (`2026-10-25/`), a timestamp or a chat title, and never create `work/` + `outputs/` session folders, at the workspace root or anywhere else. When a chat is not tied to a project folder, save into `{{WORKSPACE}}/Tasks/Codex/<task-name>/`, named for what the task is. Version folders are `v1`, `v2`, `v3`.
- **Everything stays in the workspace**: save every file you create (scratch renders, screenshots, downloads) in your `Codex/<version>/` folder for a project, or in your `Tasks/Codex/<task-name>/` folder. Images you generate are saved to `~/.codex/generated_images/` by default: copy each one into the folder you are working in right after generating it. Never save to a temp folder or a home config folder.
- **Shared skills and setup**: custom skills live in `{{WORKSPACE}}/Agent Setup/skills/`. Each one is linked individually into `~/.codex/skills/<name>`, next to `.system` (Codex's built-in skills; never touch `.system`). When you create a skill, create it in `Agent Setup/skills/<name>/` and add the matching link `~/.codex/skills/<name>`. Edit instructions and memory in `{{WORKSPACE}}/Agent Setup/`, never through a home config link.
- **Moving folders**: never move or rename a workspace folder through the filesystem. Codex's own state (`~/.codex/config.toml`, `.codex-global-state.json`) is keyed to folder paths and breaks; re-add a moved workspace through Codex's UI.
