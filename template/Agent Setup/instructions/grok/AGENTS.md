# Global rules for Grok

- **Agents Workspace (shared multi-agent projects)**: `{{WORKSPACE}}` is the shared parent folder for work across several agents. Read `{{WORKSPACE}}/AGENTS.md` before working anywhere inside it. Short version: your agent name is `Grok`. Start work on a project with `{{WORKSPACE}}/_scripts/new-version.sh <project> Grok`, edit only the `Grok/<version>/` folder it prints, never `main/` or another agent's folder, and publish with `{{WORKSPACE}}/_scripts/publish-version.sh <project> Grok <version>`. Never hand-edit `main/` or `LAST-EDITED-BY.md`. If a project under `Projects/` is flat (no `main/` or `<Agent>/<version>/` folders), retrofit it first as AGENTS.md describes, including empty `v1/` placeholders for every other agent. Build, install and deploy anything persistent from `main/`, never from your working copy.
- **Folder names**: version folders are `v1`, `v2`, `v3`. Name project and task folders for what they hold. Never create folders named after a date, a timestamp or a chat title, and never create `work/` + `outputs/` session folders.
- **Everything stays in the workspace**: save every file you create (scratch renders, screenshots, downloads, generated images) in your `Grok/<version>/` folder for a project, or in `{{WORKSPACE}}/Tasks/Grok/<task-name>/` for one-off work. Never save to a temp folder or a home config folder.
- **Shared skills and setup**: custom skills live in `{{WORKSPACE}}/Agent Setup/skills/`, which you load through `~/.claude/skills`. Every `.md` file in `{{WORKSPACE}}/Agent Setup/instructions/grok/` loads as a rule, so keep only rule files there. Edit instructions in `Agent Setup/`, never through a home config link.
- **Moving folders**: never move or rename a workspace folder directly. Other agents' chat history is bound to folder paths and breaks silently. Follow the "Moving or renaming a folder" section of AGENTS.md.
